# Lumen

A self-driving robotaxi mod for **BeamNG.drive** (0.40), built from scratch: an original car (the **Lumen**), its own
driving stack (**Lumen Drive**), a learned driver (**Lumen NN**) and a ride-hailing app. Lumen never uses BeamNG's
built-in traffic AI.

## What it does

- **A fleet of Lumens** roams the map. Call one from the app, get in, tap a pin on the map to go anywhere, and watch
  it drive you there. Pickups snap to the nearest covered road, move when the way is blocked, and can enter parking lots.
- **Lumen Drive** (`src/lua/ge/extensions/lumen/drive.lua`): lane-following paths from the road graph, pure-pursuit
  steering in a vehicle controller, traffic lights and stop signs, a committed-yellow and junction-box discipline
  (`guard.lua`), gap acceptance for cross traffic, a 4-second prediction of every nearby vehicle, people and wall
  detection, parked-car handling (pass slowly, nudge around, or reroute), and recovery when blocked.
- **Lumen NN** (`nn.lua`): a small network (91 inputs, 64-64, 2 outputs) that picks the target speed and lane offset,
  under the same guards plus a collision shield (`shield.lua`). Switch between Drive and NN in the app.
- **Parking** (`parking.lua`): nose-in into marked spaces at stops, back out when leaving.
- **Service area** (`geofence.lua`): zones that open in tiers as capabilities grow.
- **The app** (`src/ui/modules/apps/LumenRobotaxi`): map with tap-to-go, ETA, the car's "thinking" feed, a live
  lidar view from the Lumen's sensor, and the Drive / NN switch.
- **The car** is generated by code (`generator/`): body surface, panels, interior, wheels, materials, textures and the
  JBeam physics, with an adjustable level of detail (`LUMEN_DETAIL`, `LUMEN_BODY_DETAIL`).

## Layout

| folder | what |
|---|---|
| `src/` | the mod's Lua (game engine and vehicle), UI app and scripts |
| `generator/` | builds the vehicle (mesh, JBeam, materials, textures) and assembles the mod |
| `tools/` | `ship.py` (check, build, verify, install), `luaparse.py` (Lua parser for checks), install watcher |
| `testenv/` | test instance control over BeamNG's MCP server, in-game tests (drive, rides, tap-to-go, A/B, hard scenarios), and offline LuaJIT tests of the real Lua (`lua_harness.py`) |
| `training/` | the driving simulator, the brains, training and evaluation code, results (`training/README.md`) |

## Build and install

```
py tools/ship.py --check-only     # parse every Lua file, no build
py generator/build.py quick       # rebuild the vehicle into mod/
py tools/ship.py                  # build the release zip and install it into BeamNG's mods folder
```

`tools/ship.py` never replaces the mod while BeamNG is running; a background watcher installs it when the game closes.
Any argument other than `--check-only` / `--keep-vehicle` runs the full ship.

## Tests

- Offline, no game needed (LuaJIT through `pip install lupa`):
  `py -3.12 testenv/nn_offline_test.py`, `py -3.12 testenv/lidar_offline_test.py`, `node testenv/lidar_ui_test.js`.
- In game, on an isolated test instance (`py testenv/game.py start`, which refuses while another BeamNG runs):
  `drive_test.py`, `ride_test.py`, `tap_test.py`, `ab_test.py`, `hard_scenarios.py`.

## Lumen NN: honest status

The network was trained in the simulator in `training/` and compared with Lumen Drive under a decision rule written
down before each held-out test. In four attempts no trained network beat Drive by that rule: the learned versions
gained about 11% progress but had more incidents. The shipped network (with its guards and the collision shield) is
about as safe as Drive at the same progress. All numbers, including the failures, are in `training/README.md`.

## Not included
